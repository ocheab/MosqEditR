# Step 05b scoring reconciliation: MosqEditR release candidate

## Evidentiary status

The original uploaded, verbatim `05b_crispr_exon_aware_validation.R` calculates an exon-aware score with coefficients **0.40, 0.25, 0.20, 0.15**, and repeats these coefficients in its explanatory comment and generated provenance. The frozen `data_processed/05_crispr_editability.csv` in `MosqEditR_Phase2_Targeted_Extraction1.zip` instead reproduces with **0.35, 0.25, 0.25, 0.15** across all 205 genes (maximum numerical difference approximately 6.66e-16). Its corresponding `05_crispr_editability_provenance.csv` also describes 35/25/25/15. The 40/25/20/15 alternative reproduces only 1 of 205 scores within tolerance 1e-12 (maximum absolute difference 0.05).

The correction is a **retrospective code/output reconciliation** supported by the frozen analysis, not an assertion that the reconstructed file is the exact historical executable or that every upstream Step 05b transformation has been rerun. Keep both the historical uploaded script and the corrected release script in version control, or retain the historical script via Git commit history. Do not replace, recalculate or alter the archived result files.

## Changes made to the corrected source

1. Update the abundance coefficient from `0.40` to `0.35` and the transcript-coverage coefficient from `0.20` to `0.25` in the Step 05b score.
2. Make the same updates in the explanatory code comments and the `05b_crispr_exon_aware_provenance.csv` text generated by the script.
3. Fail fast when the nominal `data_processed/05_crispr_editability.csv` input already contains Step 05b output columns; running Step 05b twice on its canonical alias is not safe.
4. Save `data_processed/05_crispr_editability_pre05b.csv` before overwriting the canonical filename used by downstream steps. Abort instead of overwriting an existing backup. Execute the pipeline in a fresh working copy, not in the frozen archive.
5. Recalculate the checksum file **after** the alias copies, so hashes of the canonical output and the preserved original input refer to the final contents.

These protective changes deliberately affect how a **future execution** handles data. They do not prove that the whole analysis has been replicated, and the modified script should not be labelled “exact original executed source.”

## Verification

The accompanying `verify_frozen_editability_scores.R` is read-only and accepts the archived ZIP or extracted `05_crispr_editability.csv`. It verifies the numerical reconstruction of the final scores only. Reproducing guide enumeration, site coordinates and final gene ranking requires the full underlying data, source scripts, exact dependencies and rerunning the pipeline from a clean working copy.

Example from WSL:

```bash
Rscript verify_frozen_editability_scores.R /path/to/MosqEditR_Phase2_Targeted_Extraction1.zip
```
